## 测量口径

浏览器对照必须使用相同固定评审、相同保存的会话字节、Chrome 版本、视口、语言、外观及运动设置。分别测新进程/新 context 的首次画布可用、重载、场景切换、B/R 切换、长统一与并排 diff；数据/节点/连线实际就绪后，再等两个 animation frame。同步收集 Long Task、主线程脚本/布局耗时及预计算请求，避免把仅接口变快当成页面变快。

正式采样逐组串行，轮换版本顺序，不与构建、race 测试或其他基准并行。初次未命中、内存复用、重启磁盘命中单独记录；没有清空 OS 文件缓存，不称为物理冷盘。Node 与 Go 的源码、算法与预计算方案均有变化，这组对照代表两个实际产品版本，不能将全部差异归因于语言。

服务端基础对照单独使用相同网页资源，排除资源大小差异。固定 R10/200 条意见、9 条历史记录、约 1.1 MB JSON，每侧 5 次交错启动、每次 5 次预热后采 25 次 current GET。计时包括完整响应体，不包括客户端 JSON 解析。原始数据：`.scratch/backend-node-go-baseline.json`。

## 优化的验证门槛

本轮先复现预热调度：同一批 24 个独立 diff/布局任务，基线 `PeakActive=1`。`TestWarmIndependentJobsOverlap` 在优化前失败，日志位于 `.scratch/prewarm-baseline-proof.log`。同一测试必须在优化后通过，并保留任务数、结果 key、取消和停机边界。

`BenchmarkWarmSession` 使用 4 个场景各 18 个节点，含 16 对源码；两种输入分别使用 authored 坐标与必须走 Dagre 后备的重复坐标。每轮新建计算引擎、不写磁盘缓存，测整个可选预热过程，包含会话投影、调度、原生/后备计算和内存缓存序列化。它是后端调度基准，不代表浏览器收益。

## 后端基础对照

| 指标 | Node 0.8.7 | Go 迁移基线 |
| --- | ---: | ---: |
| 进程就绪中位 ms | 206.33 | 23.97 |

启动每侧仅 5 个样本，p95 是该小样本的最大值；Go 首次执行冻结副本出现明显离群值，不能只报中位数或承诺每次启动更快。两端 current 正文均为 148140 字节，热读取延迟接近，没有据此修改会话读取逻辑。

## 已保留的预热调度改进

预热先收集独立任务，再由最多 3 个后台调用者派发到原有最多 4 个计算 worker；CPU 配额较小时进一步降低并发，尽量留出交互容量。没有为每条边或每段源码创建无界 goroutine；总任务、结果 key、取消、共享计算和同会话写入语义保持不变。

使用冻结源码与优化源码编译相同 service 测试程序，三轮交错运行。原始数据 `.scratch/prewarm-controlled-comparison.json`。

| 指标，中位数 | Go 迁移基线 | 并行预热 |
| --- | ---: | ---: |
| authored 场景整批预热 ms | 3.34 | 2.63 |
| Dagre 后备场景整批预热 ms | 128.96 | 77.37 |
| 测试进程峰值 RSS MiB | 38.05 | 43.06 |

这是包含两种场景的测试进程资源统计，不是正式 daemon 的峰值 RSS。并发增加了一定内存和调度分配，不能将三 worker 解读为三倍提速，也不能直接等同于浏览器收益。这些调度数字与下面的浏览器结果分别记录，不混为同一个加速比。

## 页面瓶颈与保留的加载改进

冻结 Node 与冻结 Go 的空载复核各 5 轮，代码 diff 首开都稳定在约 382 ms。首个样本的代码模块下载仅约 2 ms，视图仍在等待；已安装 React DOM 开发源码也有 `FALLBACK_THROTTLE_MS = 300`。实际修改仅把首次编辑器展示从 `lazy/Suspense` 改为显式异步加载状态，再用同一测量复核。

保留动态 import 与独立代码包，未提前给所有页面加载 CodeMirror。已加载组件在模块内复用，关闭重开无需再次等待；卸载后不提交迟到状态。加载失败局限在代码页，提供中英文刷新提示，其余详情与画布仍可用。新增浏览器用例覆盖模块加载失败与刷新恢复。

## 最终三版页面复测

Chrome 156.0.8078.75 / Playwright 1.64.1，Apple M4 Pro/macOS arm64。每版 7 轮，共 21 个样本，版本顺序轮换，采样时不运行构建或其他基准。1440×1000、纸面浅色、中文、`reducedMotion=reduce`，不做 CPU/网络限速，不清 OS 缓存。图和差异实际就绪后再等两帧，计时从页面内获取。

同一 session 为 1504100 字节，SHA-256 `103032fc51882b208eb58cd624f12cc93ab7441f8ff449660cb31f7a08a9d0eb`；两场景各 45 个当前节点、46 个基线节点，含分支/返回边及实际历史 App.tsx 长片段。图结构是合成负载，不证明业务语义。

最终程序 SHA-256：`d1d05f00e9d12317b1fff139fc354e388e33ab6ed0aca2dbded44db6c3ac06e4`。首轮只有并行预热的中间程序 `1d55db8a...` 已单独保留；诊断结果未显示其单页收益，最终版同时包含加载边界修复。
