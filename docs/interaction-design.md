# LogicMargin 交互优化提案

状态：方案已确认，首版交互已接入本地网页；实现边界见文末记录。
保留已确认的操作流程、业务状态、工具风格和随系统切换的明暗主题，流程详见 [产品方案](design-proposal.md)。

核心建议：**让批注跟着对象出现，长讨论按需进入侧栏；始终只有一个编辑器、一份草稿。**
下面的收益是设计预期，尚未通过真实用户测试验证，不作效率或误操作率承诺。

## 3. 推荐交互规则

### 规则一：画布优先，面板按需出现

左侧保留场景入口；顶栏保留当前版本、本轮状态和主要提交操作。
右侧在查看业务细节、完整讨论或复核时打开，允许固定和收起，记住用户选择。
打开侧栏时保持所选对象可见；空间不足时先调整画布可用区域，避免浮层遮住目标和键盘焦点。
对象摘要始终显示名称与类型，版本、源码和验证证据通过展开查看。

### 规则二：选择与批注明确分工

单击节点或连线先选中并显示摘要；选择附近只出现一条“批注所选”工具条。
按住 Shift 多选，或进入可见的“框选”模式，结束选择后显示“3 个步骤”等明确目标摘要。
推荐框选默认只选节点；连线通过点击或替代列表显式加入，不自动把相连的边计入批注。
连线命中区适当加宽，悬停或选中时高亮实际连线与条件标签，避免相交线造成落点误解。
右键和快捷键作为补充；关键动作保留普通点击入口，不要求用户记住右键或双击规则。

### 规则三：快速写作靠近目标，长讨论展开

点击“批注所选”后，在目标旁打开非模态气泡，展示目标摘要、一个正文框和“保存批注”。
气泡避开目标、窗口边缘和当前焦点；用户可继续检查邻近步骤，不必先结束写作。
需要阅读长回复或对照依据时，点“展开到侧栏”，同一讨论和草稿转入侧栏，原气泡收起。
同一时刻只保留一个编辑位置；图标记、气泡、侧栏均引用同一条意见。
新建其他位置的批注前，先保存原目标草稿；正在输入时点击其他步骤，不悄悄改变这份草稿的目标。

### 规则四：已有意见作为稳定的图上标记

保存后在对应节点、连线或组选区边缘显示编号标记；多条意见显示数量，点击后选择讨论。
标记不覆盖业务标题，状态用文字和视觉标识共同表达，明暗主题下含义一致。
点击标记时同步定位并高亮目标，侧栏或气泡只展示当前讨论；退出后保持刚才的阅读位置。
目标被删除时保留历史片段和“原步骤已移除”提示，继续使用既定版本规则，不猜测替代落点。

### 规则五：草稿保护与轻反馈

草稿按目标保存；收起、外部点击、Esc、切换面板和切换主题后可继续输入。
正文为空时提示可以写什么；保存失败时在字段旁给出原因和重试动作，原文字保留。
保存成功后更新图上标记与待提交数量，显示“已保存，尚未提交”，不额外弹庆祝提示。
桌面支持 Ctrl/Cmd+Enter 保存；中文输入法组合输入期间不把按键误当提交。
Esc 收起编辑器并归还焦点；再次按 Esc 才清除选择，避免一次操作同时丢掉写作和定位上下文。

### 规则六：提交入口稳定，状态不含糊

顶栏保留“提交本轮（N）”，旁边区分尚未提交的已保存意见与未保存草稿。
汇总在页面内展开，能检查版本、范围和意见；正常提交不再叠一层重复确认窗。
存在未保存输入时，明确提供“保存后提交”和“保留到下一轮”，不默认丢弃。
提交中显示进行状态并防止重复提交；失败后可重试，沿用固定内容与幂等规则。
保存、提交、代理接收、处理中和返回结果继续分别显示，不因按钮点击就提前声称代理已接收。

### 规则七：复核围绕一条意见连续进行

打开待复核意见时，面板依次呈现“原意见、代理回应、本次相关变化”，展开项保持短而可读。
画布定位到相应业务片段，突出新增、修改、移除；默认保留一张主图，按需打开旧版对照。
用户确认后可选择“确认解决并看下一条”；“仍需调整”保留原讨论并追加说明。
单条解决与本轮通过沿用已确认的状态边界，不能为了少一次点击自动通过整轮。
没有待复核意见时显示本轮范围和明确的“通过本轮”入口，不留一个没有解释的禁用按钮。

### 规则八：概览找位置，阅读看细节

概览层展示场景、业务标题和意见标记；阅读层再展开条件、数据变化和失败结果。
适应全图时不把完整说明缩成难以辨认的小字；点击对象进入可读层级，返回后恢复原视角。
源码、验证详情和历史记录按需展开，保持业务正文的连续性。

## 4. 桌面、触控与键盘

| 输入方式 | 推荐操作 |
| --- | --- |
| 鼠标/触控板 | 点击选中、Shift 多选；显式框选模式；浏览模式平移；写作气泡与讨论侧栏可互转 |
| 触控 | 明确的选择/多选入口；点击列表可组成选区；批注在画布下方或 sheet 展开，保留目标摘要 |
| 键盘 | 按正常 Tab 顺序到达节点、连线替代列表和操作按钮；Enter/Space 选择；明确写作后进入正文；Esc 返回入口 |

拖动不是唯一选择方式；列表中的点击选择和键盘操作必须能完成同一目标。
触控可交互区域推荐约 44 CSS px 并避免互相重叠；这是本项目的体验目标，不将其误写成所有网页的法定最低尺寸。
UI/UX Pro Max 的网页目标尺寸规则采用 WCAG 2.2 AA 的 24 CSS px 及适用例外，触控体验需结合实际设备验证。
移动端避免自动拉起软键盘；sheet 中长内容可滚动，输入、保存和关闭操作保持可达。
焦点样式、控件标签和错误消息可被辅助技术识别；定位动画可打断，并尊重减少动态效果设置。

## 6. 优先级与可用性验证

**优先完成**：统一编辑器与草稿、非模态快速批注、明确选择目标、可发现的图标记和触控替代入口。
**随后验证**：按需侧栏、保存后的继续阅读、稳定提交入口、连续复核与新旧变化定位。
**后续优化**：大图的概览/阅读层级、更多快捷键和更精细的讨论导航，不为首版增加新的操作流程。

建议用以下任务邀请策划/产品和开发者分别试用；先观察能否独立完成，再记录卡住的位置和原因：

1. 不使用右键或快捷键，给一个节点和一条连线分别留意见，并准确指出各自落点。
2. 选择“检查额度 → 扣点 → 启用集成”，只批注这三个步骤，说明选区里是否包含连线。
3. 输入一半意见后收起、查看另一节点、重新打开，再移到侧栏；原目标和文字仍保持。
4. 保存一条意见，继续看图，然后提交本轮；能解释“已保存”和“已交给代理”的区别。
5. 阅读长代理回应并复核变化，确认一条、保留另一条待调整，完成后仍知道当前版本与本轮状态。
6. 用触控和纯键盘重复主要任务，检查软键盘、焦点、长文本和系统主题切换是否阻碍操作。

待验证的假设：气泡是否遮挡关键分支；侧栏按需展开是否易发现；编号标记是否足够清楚；“确认并下一条”是否造成误解。
本轮依据源码与技能准则提出方案，没有真实用户实验、性能测量或完成率数据；当前也未核实 Crit 的所有编辑和迁移路径。
交互演示已检查真实鼠标框选、节点与连线选择范围、草稿恢复、单编辑器互转、快捷键保存和 320px 布局；界面内的主流程断言通过。
演示使用内存中的示例数据，草稿刷新后会重置；正式设计仍要求草稿可持久恢复。
以上演示用于方案确认；正式网页的实现与自动验证见下节，交互收益仍需真实用户任务验证。
