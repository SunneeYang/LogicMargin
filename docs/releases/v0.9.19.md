# LogicMargin 0.9.19

Codex now loads MCP directly from the installed plugin. Initialization and tool discovery work without an already-running review backend; the first tool call starts or reuses the shared service. If that backend exits, the next call can restore it. Operations already sent are not replayed automatically, so a lost response cannot silently cause another publication or reply.

The bundled compatibility manifest resolves its launch entry relative to the plugin root and keeps the 24-hour tool budget. Codex no longer needs a global executable path that changes with plugin versions. `server setup` remains a compatibility alias for `server start` and no longer writes Codex configuration. The HTTP MCP endpoint remains available to DSH and existing clients.

For an upgrade, verify the old managed service, stop it and back up its actual data directory. Preserve the same home, port and review IDs. If a global `mcp_servers.logic_margin` entry exists, confirm its ownership, preserve its tool policy, and remove or disable only that old registration. Reload the plugin/MCP connection after installation; an existing stdio process does not switch versions in place.

Git marketplace automatic MCP launch uses the existing macOS/Linux shell launcher. Windows automatic registration uses its native platform ZIP; the PowerShell launcher remains available for CLI use. Native ZIPs require no Node.js or Go installation. DSH retains its existing HTTP integration and the `0.2.2-rc.1` host-interface baseline. GitHub and npm publication are separate steps; `@latest` selects the registry version at installation time, not an automatic update policy.

This release supplies five native platform ZIPs, the versioned DSH tgz and SHA-256 checksums. The fixed DSH fallback names are `dsh-plugin-logicmargin.tgz` and `dsh-plugin-logicmargin.tgz.sha256` under the latest Release download endpoint.

Local macOS acceptance covered a new real Codex session, all 11 tools in an isolated installed-package workflow, shared writers, backend crash recovery, reconnect, archive and restore. One tool call waited **310 seconds** and returned only after the test fixture submitted approval. That is not a full 24-hour duration test or Windows device acceptance.

---

- Codex 改为随包注册 stdio MCP，以插件根目录解析相对入口；初始化和工具列表查询不依赖后台预先运行。
- 实际工具调用按需启动或复用后台，后台退出后由下一次调用恢复；已发出的操作不自动重放。HTTP MCP 和 DSH 接入保留。
- 兼容清单保留 24 小时工具预算；移除全局绝对路径注册和升级路径迁移。`server setup` 仅保留为启动后台的兼容别名。
- 升级继续沿用原 home、端口、session、批注和历史；确认归属后清理旧全局入口，并保留原工具策略。安装后需要重载宿主连接。
- macOS/Linux Git 启动器与五平台原生 ZIP 分别提供入口；Windows 自动注册使用平台 ZIP。DSH 默认安装 `@latest`，同时保留固定 `@0.9.19` 与版本化 tgz 的复现方式，npm 是否可用以 registry 为准。
- 本机安装版全部 11 个工具和故障恢复通过，单次等待实测超过 310 秒；未把它表述为完整 24 小时等待或 Windows 实机验收。
