# 虚构订阅工作区演示来源

默认评审 `demo-subscription-v1` 完全依据本仓库原创的 [订阅规则](../examples/subscription.md)。它用于展示流程阅读、批注和版本复核，不来自实际业务工程，也不代表任何生产订阅、支付或通知实现。

- 入口：[src/sample.ts](../src/sample.ts)，由 App 直接导入，因此网页构建和 Go 原生发行都会携带此演示。
- 形状：3 个独立场景、24 个节点、27 条连线；初始批注为空。
- 场景：套餐升级、集成启用、通知渠道选择。点数没有货币价值，通知仅生成预览。
- 证据：节点指向 `examples/subscription.md` 对应规则段落，不包含真实业务源码。行号从 1 开始，含首尾行；digest 为这些行以 LF 连接后的 UTF-8 SHA-256，不含末行换行，与 CLI 来源核验一致。
- 快照：`snapshot.files` 保存规则文档完整字节的 SHA-256；fingerprint 为紧凑 `JSON.stringify(files)` 的 UTF-8 SHA-256。`synthetic-v1` 是演示版本标记，不是 Git 提交。时间仅表示演示材料的编写日期。

场景各自从示意状态开始，不是一次请求的连续步骤。规则文档的节点 ID 是稳定交互锚点，不表示与外部系统存在对应关系。修改规则后须同步摘要与行号；`src/public-examples.test.ts` 校验文档、证据、图形规模和原型副本。

新演示拥有独立文档 ID，不合并其他评审的批注、草稿或历史。已有本地记录和真实会话不会被删除；用户可继续打开自己的旧记录。

此演示不验证并发、外部服务、事务、部署或线上行为。交互测试只能证明其断言覆盖的 LogicMargin 功能，不能证明虚构业务已实现。
